# 1.4.0

## What changed

The knowledge-base intake step passes on a fresh install. `acp kb scaffold` builds the `lite`
level from the source tree: a survey, one profile per feature with every citation resolving to
a file and line, the status matrix, and the bound source index. `standard` and `full` are
higher levels, and `acp kb status` lists the profiles short of the configured one.

The `packs/` directory is now `playbooks/`, the `bin/pack` driver is `bin/playbook`, skill
packs are skill sets and agent packs are agent sets; the old names still work and an install
moves an existing `packs/` directory to `playbooks/`.

Three rules that only ran as Claude Code session hooks now run in `acp check`, and so in the
pre-commit hook and CI: UI drift, formatting, and type errors. A git `pre-push` hook refuses a
force push to or deletion of a shared branch. Slash commands and skills can be printed as text
with `acp command` and `acp skill`, so an agent without Claude Code can follow them.

## Where the changes came from

A review of a fresh install found that the knowledge-base step could only pass after an agent
had done work the tool never started, and that a large part of the enforcement was wired into
hooks that only Claude Code runs. Both are fixed in this release.

## Still open

- Work-order state folders and `acp release` for the project's own release notes.
- The `standard` and `full` levels are written by an agent. The tool scaffolds and measures.
- Database drops, destructive shell commands, and `--no-verify` are only caught inside Claude
  Code, because they are commands rather than changes to files.
