# 1.3.0

## What changed

Install opens six intake work orders, each with a finished spec and a test suite. The project
is operational when all six have closed on a passing run. `acp intake inventory`
classifies the repository before anything is adopted. The knowledge base is the eight-phase
repository analysis run against the project's own code, with a source index that records a
content hash per cited file; `acp kb status` reports what is current, stale, or broken,
`wo close` names the profiles a change touched, and `acp check` carries the rule into CI.

Also in this release: two complete behavioural example suites, the section on stubbed
end-to-end tests restored to the methodology, and three assertion helpers.

## Where the changes came from

The intake steps, the adoption path, and the baseline come from the report of installing the
pipeline into an existing monorepo (see 1.2.0). The knowledge base already existed as the
documentation lifecycle for other people's code; it had never been run against the project
itself and could only be started from Claude Code. The in-place adoption path came from the
first inventory run, which proposed adopting the pipeline's own intake work orders.

  rewrite a profile.
