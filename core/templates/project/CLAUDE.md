## Code Quality Standards

### Production-Level Code Only

1. **NO hallucinated code** - Verify files/tables/methods exist
2. **NO placeholder implementations** - Every function complete
3. **NO fake outputs** - Only report real execution results
4. **NO assumptions** - Investigate if unsure
5. **VERIFY everything** - Check existence before referencing

### What We Will NOT Accept:
- `// TODO: implement this later`
- `throw new Error('Not implemented')`
- Code referencing non-existent files/tables
- Test results that were not actually executed

### MANDATORY: Pre-Implementation Checklist

Before writing any code, verify:

- [ ] **Configuration over hardcoding** - Using config/settings instead of magic numbers?
- [ ] **Error handling complete** - Proper error messages and exception handling?
- [ ] **No debug/dev code paths** - No `console.log`, dev fallbacks, or test stubs?
- [ ] **Following existing patterns** - Matches the codebase's established conventions?

### MANDATORY: Self-Review Before Declaring Done

Before marking any work as complete:

- [ ] **Read through ALL changed files** - Line by line review
- [ ] **Remove console.log statements** - Use proper Logger service instead
- [ ] **Check for magic numbers** - Extract to configuration or constants
- [ ] **Verify proper typing** - No `any` types, proper validation
- [ ] **Validate error handling** - Clear messages, proper exception types

### Production Mindset Questions

Ask yourself before completing any implementation:

1. **"Would I deploy this to production right now?"** - If not, fix it first
2. **"Would a code reviewer approve this?"** - No shortcuts or bandaids
3. **"Does this match the quality of the existing codebase?"** - Consistency matters

### Anti-Patterns to Avoid (Lessons Learned)

These mistakes have caused rework in the past:

1. **Test-Driven Tunnel Vision**
   - Tests passing ≠ production-ready code
   - Don't stop when tests pass; review the implementation quality

2. **Incremental Patching**
   - Don't just fix the immediate problem and move on
   - Step back and review the whole implementation after changes

3. **Expedience Over Quality**
   - Don't leave debug logging in place
   - Don't copy-paste values; abstract them properly
   - Don't skip cleanup after fixing bugs

4. **Ignoring Project Standards**
   - Re-read CLAUDE.md requirements before declaring work complete
   - Follow the mandatory checklists above

### Implementation Principles

When implementing features:

1. **Start with the proper pattern** - Use configuration, proper logging, and error handling from the beginning
2. **Clean as you go** - Remove debug code immediately after solving the problem
3. **Self-review before completion** - Read through all changes with a "production deployment" lens
4. **Follow project standards** - Re-read CLAUDE.md requirements before declaring work complete
